# Validation

## Acceptance Criteria

A processed dataset is backtest-ready only when:

- It follows the Yahoo-compatible schema.
- It starts at the first available trading observation at or immediately after `1970-01-01`, unless an exception is documented.
- It has no duplicate dates.
- It has no non-positive `Close` or `Adj Close` values where those fields are populated.
- Its return columns recompute from level columns within the documented tolerance.
- It has been compared against at least one independent source over an overlapping period.
- Any source splice, reconstruction, or missing OHLCV field is documented.

## Required Test Categories

### Schema Tests

- Required Yahoo-style columns exist and are ordered first.
- `Date` parses as datetime.
- Numeric columns parse as numeric or blank.
- Project-specific columns do not replace Yahoo-style column names.

### Coverage Tests

- First date is at or immediately after `1970-01-01` for trading-day datasets.
- Last date is not unexpectedly stale relative to the source retrieval date.
- Dates are unique and sorted ascending.

### Arithmetic Tests

- `Price Return` equals `Close / previous Close - 1` within tolerance.
- `Total Return` equals `Adj Close / previous Adj Close - 1` within tolerance when `Adj Close` is a true total-return level.
- For `USLCAP`, `Adj Close` must be populated from the first trading observation after the `1970-01-01` anchor, and `Total Return` may be blank only on the first row.
- Return calculations skip the first valid row and do not use calendar-day forward filling.

### Independent-Source Tests

- Compare overlapping `Close` values against an independent source such as FRED `SP500` for recent S&P 500 price-index levels.
- Use documented tolerances for source timing, rounding, and holiday differences.
- Log all mismatches above tolerance.
- The initial FRED fixture uses a `0.01` index-point tolerance because Yahoo stores more decimal places than the rounded values displayed by FRED.
- For the pre-`^SP500TR` USLCAP period, daily `Total Return` must match the raw Kenneth French / CRSP `Hi 30` daily return source exactly within rounding tolerance.
- For 1970-1987, annual compounded USLCAP adjusted returns should remain within a documented sanity-check band versus an external S&P 500 total-return annual reference. This is not an exact-match test because the source is a CRSP large-cap proxy, not official S&P 500 total return.
- For Gold (`GOLDPM`, GLD-tracking), `Close` must match the raw LBMA Gold PM USD source exactly on LBMA-fix rows (pure spot) and `Price Return` must recompute from it. `Adj Close` is a GLD-tracking total-return index: it must equal `Close` on the first row and end below `Close` (carrying GLD's fee drag); `Total Return` must recompute from it. In the model segment (1970→2004), `Total Return` must equal `spot price return × (1 − 0.0040·days/365)`. The observed segment runs on **GLD's (NYSE) trading calendar** so the dataset aligns with GLD day-for-day (a London-calendar series compared to a US-calendar ETF by intersecting daily returns drifts ~+47% over 2004-2026); its dates must equal GLD's trading days exactly, `Adj Close` must be exactly proportional to raw `GLD` adjusted close (constant ratio within 1e-9), and UK-bank-holiday rows (no LBMA fix, `..._close_gld_step`) carry a GLD-stepped `Close`. The pre-2004 fee model, the LBMA-PM-fix timing basis, and the model-era London calendar are documented caveats; a US-close base (COMEX futures) is a deferred daily-fidelity upgrade.
- For short-term U.S. Treasuries, the model-derived public dataset must start on the first trading observation after 1970, include a Federal Reserve yield-curve model segment at 2-year maturity with coupon carry, and match raw Yahoo VFISX/SHY adjusted-close daily returns within tolerance by observed fund segment. The Fed model segment must show substantial cumulative `Adj Close` growth (reflecting the high short-rate environment of the 1970s–80s). A future CRSP/constituent-level upgrade must additionally validate issue-level return calculations and compare post-2002 cumulative behavior against SHY.
- For intermediate-term U.S. Treasuries, the model-derived public dataset must start on the first trading observation after 1970, include a Federal Reserve yield-curve model segment at 8.5-year maturity with coupon carry, and match raw Yahoo VFITX/IEF adjusted-close daily returns within tolerance by observed fund segment. The Fed model segment must show cumulative `Adj Close` growth well above its starting level by the time VFITX begins. A future CRSP/constituent-level upgrade must additionally validate issue-level return calculations and compare post-2002 cumulative behavior against IEF.
- For long-term U.S. Treasuries, the model-derived public dataset must start on the first trading observation after 1970, include a Federal Reserve yield-curve model segment with coupon carry, and match raw Yahoo VUSTX/TLT adjusted-close daily returns within tolerance by observed fund segment. A future CRSP/constituent-level upgrade must additionally validate issue-level return calculations and compare post-2002 cumulative behavior against TLT.
- For the 3x U.S. large-cap (UPRO-like) `USLCAP3X` derived dataset, the series must start on the first trading observation after 1970 with `Close == Adj Close` (a single 3x daily-reset total-return NAV) and `Price Return == Total Return`. The synthetic segment must be exactly reproducible by recomputing the daily-reset model `lev_ret = 3*u - 2*((IRX/100 + spread)*days/360) - 0.0091*days/365` from the raw `USLCAP` total returns and raw `^IRX`, compounded continuously; the observed segment daily returns must exactly match raw `UPRO` adjusted-close returns. There must be exactly one synthetic→observed transition at UPRO inception. Independent validation recomputes the model over the UPRO live overlap and requires daily-return correlation > 0.99 and cumulative growth within 10% of actual UPRO; the calibrated borrowing spread targets a ~1.0 cumulative ratio. Validation cannot prove pre-2009 daily path accuracy — the leveraged series is model-derived and path-dependent, not observed UPRO history, and must never be treated as a simple 3x multiple of long-horizon S&P 500 returns.
- For the 3x long-term Treasury (TMF-like) `LTT3X` derived dataset, the series must start on the first trading observation after 1970 with `Close == Adj Close` (a single 3x daily-reset total-return NAV) and `Price Return == Total Return`. The synthetic segment must be exactly reproducible by recomputing the daily-reset model `lev_ret = 3*u - 2*((IRX/100 + spread)*days/360) - 0.0106*days/365` from the raw `LTT` total returns and raw `^IRX`, compounded continuously; the observed segment daily returns must exactly match raw `TMF` adjusted-close returns. There must be exactly one synthetic→observed transition at TMF inception (2009-04-16). Independent validation recomputes the model over the TMF live overlap and requires daily-return correlation > 0.99 and cumulative growth within 10% of actual TMF; the calibrated spread targets a ~1.0 cumulative ratio. Validation cannot prove pre-2009 daily path accuracy, and the most important caveat is the duration/exposure mismatch before 2002 (the `LTT` underlying is a Fed 25-year par model and VUSTX, not the ICE 20+ Year index TMF tracks). The leveraged series is model-derived and path-dependent, not observed TMF history, and must never be treated as a simple 3x multiple of long-horizon long-Treasury returns.
- For the 3x intermediate-term Treasury (TYD-like) `ITT3X` derived dataset, the series must start on the first trading observation after 1970 with `Close == Adj Close` (a single 3x daily-reset total-return NAV) and `Price Return == Total Return`. The synthetic segment must be exactly reproducible by recomputing the daily-reset model `lev_ret = 3*u - 2*((IRX/100 + spread)*days/360) - 0.0109*days/365` from the raw `ITT` total returns and raw `^IRX`, compounded continuously; the observed segment daily returns must exactly match raw `TYD` adjusted-close returns. There must be exactly one synthetic→observed transition at TYD inception (2009-04-16). The genuine 3x 7-10yr ETF is Direxion TYD (ProShares UST is a 2x fund). Independent validation recomputes the model over the TYD live overlap: because TYD is thinly traded with stale/illiquid Yahoo closes in 2014-2018, the calibration target is **cumulative** growth within 10% of TYD (robust to mean-reverting noise), the strict daily-correlation check (> 0.95) is applied to the clean recent era (2019+), and the full-overlap correlation need only exceed 0.85. The leveraged series is model-derived and path-dependent, not observed TYD history, and must never be treated as a simple 3x multiple of long-horizon intermediate-Treasury returns.
- For the 2x gold (UGL-like) `GOLD2X` derived dataset, the series must start on the first trading observation after 1970 with `Close == Adj Close` (a single 2x daily-reset total-return NAV) and `Price Return == Total Return`, and follow the gold (LBMA) trading calendar. The synthetic segment must be exactly reproducible by recomputing the daily-reset model `lev_ret = 2*u - 1*((IRX/100 + spread)*days/360) - 0.0095*days/365` from the raw `GOLDPM` **`Price Return`** (pure spot — GOLDPM's Total Return now carries GLD's fee drag) and raw `^IRX`, compounded continuously; the observed segment daily returns must exactly match raw `UGL` adjusted-close returns (computed against the most recent UGL close). The synthetic segment runs through UGL inception (2008-12-03); there must be **no synthetic fills in the observed era**. GOLD2X inherits GOLDPM's calendar, so its observed era is on the NYSE (GLD/UGL) calendar — every observed row lands on a UGL trading day and the holiday-flat path is effectively unused (≈0 rows; any such rows carry `Total Return == 0`). **Regression guard:** in the observed era `Adj Close` must be an exact constant multiple of raw UGL (the earlier build double-counted holiday moves and ran +33.8% above UGL over 2008-2026, and a London-calendar GOLD2X drifted ~+2%/yr vs UGL in a return-intersection backtest; both are now fixed and tested). Because `GOLDPM` is the LBMA PM fix (~10:30am ET) and UGL closes at 4pm ET, the daily UGL-vs-continuous-model correlation is only ~0.67 (a US-close gold ETF like GLD tracks UGL at ~0.997); the spread-calibration check is recomputed on **raw LBMA-calendar** spot returns and targets cumulative growth within 10% of UGL and a daily volatility ratio within 0.80-1.20, with correlation only required to exceed 0.5. The leveraged series is model-derived and path-dependent before 2008, not observed UGL history, uses LBMA spot rather than UGL's futures benchmark, and must never be treated as a simple 2x multiple of long-horizon gold returns.
- For broad commodities, the dataset starts on 1970-01-02 and anchors the 1970-1991 history to the S&P GSCI **Total Return** index (roll yield + T-bill collateral + GSCI production weights), obtained from MacroMicro's free ~bi-monthly republication and committed as a static file. `Close`/`Price Return` is the excess-return (spot+roll) level; `Adj Close`/`Total Return` is the total-return level, and `Adj Close >= Close` everywhere. Segment 0 (1970-1983) log-linearly smooths the anchor to daily `^IRX` trading dates (no free daily broad-commodity data exists before 1984), and is flagged model-derived. Segment 1 (1984-1991) overlays the genuine daily `^SPGSCI` spot **shape** per anchor interval, so it must carry realistic daily volatility (annualized > 8%) while `Adj Close` stays within 5% of the GSCI TR anchor at sample dates. The BCOM segment `Price Return` must exactly match raw `^BCOM` close daily returns. The DBC segment `Price Return`/`Total Return` must exactly match raw DBC close/adj-close daily returns. Within Segment 1, `Adj Close / Close` must grow by >1.3x as collateral compounds. All four quality flags must be present with row counts within expected ranges. Validation cannot prove Segment 0 daily volatility, daily-resolution GSCI total-return levels (the anchor is downsampled), or DBC gross index total return; those remain documented gaps requiring licensed daily futures/index data.
- For CPI inflation, month-start `Close` values must exactly match raw BLS `CUSR0000SA0` monthly observations. Calendar-daily rows must be unique, sorted, and gapless from 1970-01-01; interpolated rows must be flagged as model-derived and latest-month carry-forward rows must be separately flagged. Validation must not describe the interpolated rows as observed daily inflation data.
- For global stocks (`GLSTOCK`), the early 1970-1989 model segment must compound to the documented MSCI World gross annual total return in each calendar year while remaining flagged as model-derived. The Fama/French developed-market segment must match raw `Mkt-RF + RF` daily returns exactly within tolerance, and the VT segment must match raw Yahoo VT adjusted-close daily returns exactly within tolerance. Tests must preserve the caveat that this is a public-source proxy, not licensed observed daily ACWI/FTSE All-World history.
- For unhedged global bonds (`GLBOND`), the JST-anchored early segment must compound to the recomputed GDP-weighted unhedged USD global government-bond basket return in each full calendar year (the per-year overlay invariant). The observed segment must match the raw adjusted-close blend of 45% BND and 55% BWX exactly within tolerance. Regression tests guard the build: the early segment must have many distinct daily returns per year (not the previous single constant value); its annualized volatility must fall in a realistic 3%-20% band; two unambiguous USD shocks must move the basket in the correct direction (Plaza Accord 1985-09-23 up; Carter dollar-rescue 1978-11-02 down), which also guards BIS FX orientation; the basket weights must be economically sane (US largest, four largest economies > 50%), guarding the comparable-real-GDP weighting against JST's inconsistent-unit nominal `gdp`; and the daily rate leg must cover the US (from 1970), Japan (from 1986) and UK (from 1979). Validation must preserve the caveat that the 1970-2007 segment is model-derived: the annual level is anchored to JST, the path uses daily FX throughout, and the rate leg is daily only for US/UK/Japan (≈62% of the basket from 1979) and monthly elsewhere.
- For unhedged global short-term bonds (`GLSTBOND`), both level columns must recompute from their own return: `Close`/`Price Return` is gross-of-fee and `Adj Close`/`Total Return` is net-of-fee. The net-of-fee drag over the model era must match the modeled representative rate (~0.26%/yr) and `Adj Close <= Close` everywhere. The observed segment (from 2009-01-30) must reproduce the GDP-weighted, annually-rebalanced net blend `w_us*SHY + (1-w_us)*mean(ISHG, BWZ)` exactly within tolerance, where `w_us` is the US share of developed-market real GDP. Unlike GLBOND there is no JST annual overlay (the series is built directly), so regression tests instead require: the early segment is genuinely daily (>100 distinct returns/year); its annualized unhedged volatility falls in a 3%-12% band (below the 10yr GLBOND); the Plaza/Carter USD shocks move it in the correct direction; basket weights are economically sane (US largest, G4 > 50%); and the daily 2yr rate leg covers US (1970), Japan (1974-09) and UK (1979). Validation must preserve the caveat that the 1970-2009 segment is model-derived, the 2yr yield is interpolated from the 3-month and 10-year rates where no true 2yr exists, and the observed blend is a GDP-weighted SHY+ISHG/BWZ proxy, not an official global short government-bond index.

### Anomaly Tests

- Detect duplicate dates.
- Detect missing values in required fields.
- Detect non-positive levels.
- Detect unusually large single-day moves for manual review.
- Detect discontinuities at source boundaries.
- For incremental updates, confirm the stitched dataset is still unique, sorted, and return-consistent after overlapping rows are replaced.

## Test Data Policy

Small fixtures may be committed under `tests/fixtures/` if licensing permits. Larger or restricted source files should remain outside version control and be represented by manifests under `sources/manifests/`.

## Full-Suite Refresh Validation

Use `python src/update_all_datasets.py` for a one-command refresh of every processed dataset. The script delegates to the per-dataset update scripts, then runs `python -m pytest -q tests/validation` by default after all updates succeed. If `--no-tests` is used, run the validation command manually before treating the refreshed outputs as current.
