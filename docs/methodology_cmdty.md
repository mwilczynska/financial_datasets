# CMDTY — Broad Commodities

Dataset: `broad_commodities`; backtest alias: `CMDTY`.

CMDTY now uses **direct daily GSCI excess-return and total-return history**
from 1970-01-02 through 1991-01-02. This replaces the sparse-anchor smoothing
before 1984 and the spot-shape overlay from 1984 onward. The processed CSV and
Parquet use this replacement. Vendor and derived-output redistribution rights
remain unverified; publishing these files does not establish permission or a
data license.

## Definition and source chain

CMDTY approximates diversified commodity futures exposure with roll yield and
collateral income. It joins three different exposures, rather than reproducing
DBC before the ETF existed. Both growth columns start at 100 on 1970-01-02.

| Phase | Dates | Close / Price Return | Adj Close / Total Return | Quality flag |
|---|---|---|---|---|
| GSCI | 1970-01-02–1991-01-02 | GSCI excess return: spot + roll | GSCI total return: ER + collateral | `backcalculated_gsci_daily_excess_and_total_return` |
| BCOM | 1991-01-03–2006-02-06 | Yahoo `^BCOM` excess return | BCOM ER plus the existing `^IRX` collateral model | `model_bcom_excess_return_plus_tbill_collateral` |
| DBC | 2006-02-07 onward | DBC ETF close growth | DBC ETF adjusted-close growth | `observed_yahoo_dbc_dblci_total_return_etf` |

The migration retained all **14,228 observation dates**, 1970-01-02–2026-09-28:
5,255 GSCI, 3,781 BCOM and 5,192 DBC rows. Current counts and hashes are in
[sources/manifests/broad_commodities_build.json](../sources/manifests/broad_commodities_build.json).

## Daily GSCI source

The [pinned Trading_Commo workbook](https://raw.githubusercontent.com/yessinemx/Trading_Commo/f5ecf1507fb9cc98ffcc1f69c217793f5f9272a3/data/GSCI_Data.xlsx)
has 14,609 complete weekday observations, 1970-01-02–2025-12-31. Sheet
`Données GSCI` contains `Date`, `GSCI_Spot`, `GSCI_ER` and `GSCI_TR`.
The builder enforces SHA-256
`918e4046300180e0274781bfa6f1f5dcf2dc7df61b9229f9d4a9ea124da2a9f8`
and 442,834 bytes before reading it. The complete snapshot stays in the ignored
local cache `sources/raw/broad_commodities_gsci_daily.xlsx`.

The authors' companion code requests Bloomberg `PX_LAST` with daily frequency
and previous-value filling on non-trading weekdays. This supports the index-type
labels; it does not authenticate the original terminal extraction. Holiday rows
may carry prior levels. The S&P GSCI launched **May 1, 1991**; every GSCI row used
here, including the January 1991 splice endpoint, is provider back-calculation.

The [research](research/cmdty_daily_1970s_followup.md) and
[independent Astra Max review](research/cmdty_full_history_astra_review.md)
checked all 2,607 1970s TR levels against another public delivery, all 360
1970s monthly Spot/ER/TR values against an older Duke workbook, 22 published
annual TR returns, 22 dated SEC TR levels, and the user's 1979–1991 daily TR
export. These corroborate the underlying index history. They do not independently
construct or validate every daily value; daily ER has less external daily
corroboration than TR.

The historical research reports compare the pre-migration dataset. Their
original audit scripts expect that earlier dataset and builder; reproduce those
studies in an isolated checkout using the recorded baseline. The current
production checks are the contract tests and implementation review below.

The [README chart](assets/asset-class-growth.png) uses the current processed
`Adj Close` histories, including this GSCI replacement. It is generated at
1920 × 1080 pixels by `python src/create_readme_chart.py`; the companion social
preview is generated by `python src/create_social_preview.py` at 1280 × 640.
Both charts rebase the selected series to 100 over their common date range.

## Calendar and return calculation

The builder retains the original CMDTY dates, stored in
[sources/derived/broad_commodities_gsci_calendar.csv](../sources/derived/broad_commodities_gsci_calendar.csv).
Their manifest records the calendar hash and original versioned dataset.
They formerly came from IRX through 1984-01-03 and SPGSCI thereafter.
This is the project observation calendar, not a universal futures trading calendar.

Select the source **levels** on those dates before calculating adjacent returns:

```text
Close[t]       = 100 × GSCI_ER[t] / GSCI_ER[1970-01-02]
Adj Close[t]   = 100 × GSCI_TR[t] / GSCI_TR[1970-01-02]
Price Return[t] = Close[t] / Close[previous CMDTY date] − 1
Total Return[t] = Adj Close[t] / Adj Close[previous CMDTY date] − 1
```

Skipped dates' growth is included in the next selected-date ratio. Flat rows are
retained; they are not used to infer a trading calendar. First-row returns are
blank. No MacroMicro interpolation, SPGSCI overlay, or IRX stripping/addition
is applied to GSCI. Tiny negative daily TR-minus-ER spreads caused by rounded
source levels are allowed.

## Splices and migration

GSCI ends on 1991-01-02. A raw-source full build uses the incoming BCOM ratio
from its January 2 overlap to January 3. On 2006-02-07 it uses DBC's own February
6 overlap, separately for close and adjusted close. Both growth columns compound
from their respective previous endpoint, without a reset.

The implemented migration uses a versioned processed baseline because this
checkout lacks the old full Yahoo chart caches and BCOM's endpoint is unavailable.
It independently scales all subsequent Close and Adj Close levels by the new
GSCI endpoint divided by the corresponding old endpoint. This is mathematically
equivalent to compounding the old adjacent ratios from the new endpoint.
All 8,973 later return pairs, including both splice rows, are preserved.
The largest ratio changes from decimal output rounding are 2.673e-13 for Close
and 4.312e-14 for Adj Close, below the 1e-10 contract tolerance.

The baseline is Git commit `20396a64b4203cb9d06b4d096e473f268a57684b`,
CSV SHA-256 `d31df07d79f778ce48069c383342e2784d837c4d3dfbd58da921b4685f8856d7`.
An identical ignored local archive is retained. Build metadata records the
baseline Git blob, source and output hashes, independent scale factors, preserved
return counts, maximum ratio differences and both splice checks.
Later source feeds were not re-fetched or freshly verified during migration.

BCOM retains its existing collateral factor,
`1 + IRX_percent / 100 / 365` **per observation**, using forward-filled rates.
It does not accrue extra days across weekends in this model. This change leaves
that historical approximation intact. DBC's adjusted close supplies ETF total
return without an additional project collateral calculation.

## Build and update

Install `requirements.txt`, including openpyxl for the pinned workbook.

```powershell
# One-time migration of a committed processed baseline; repeat runs are unchanged.
python src\build_broad_commodities.py --migrate-gsci --root .

# Ordinary updates fetch only the recent DBC window.
python src\update_broad_commodities.py --end-date YYYY-MM-DD

# Full rebuild from permitted historical BCOM/IRX caches and live DBC.
python src\build_broad_commodities.py --end-date YYYY-MM-DD
```

Migration retains the existing end date and makes no Yahoo requests.
It captures one input byte snapshot and rejects an inconsistent manifest or
changed baseline. It validates staged CSV, Parquet, returns and hashes before
replacing outputs. A replacement failure rolls back completed replacements;
if rollback itself fails, recovery copies are retained and their paths reported.
The interim CSV is disposable. Repeat migration does not rewrite outputs.

A clean full rebuild still needs valid BCOM and IRX history or a permitted
replacement. It validates the required overlap dates and minimum coverage,
reuses valid caches, and retains them if `--refresh-historical-sources` fails.
It no longer needs the old MacroMicro or SPGSCI sources. Ordinary updates preserve
the early daily GSCI segment and its provenance, and refresh counts/output hashes.

## Validation and limitations

`tests/validation/test_broad_commodities_contract.py` verifies schema,
ordered dates, positive levels, return arithmetic, every selected ER/TR level,
the 44 published reference gates, source/fill labels, source and output hashes,
CSV/Parquet equality, segment counts and migration baseline preservation.
`tests/automation/test_cmdty_gsci_migration.py` covers selected-date ratios,
flat observations, separate splice compounding, idempotence, invalid inputs,
concurrent updates and output/rollback failures. Incremental tests protect the
daily GSCI prefix while adding new DBC rows.

Remaining limitations are GSCI's production weights and roll rules versus DBC;
retrospective pre-launch history and weekday filling; unauthenticated vendor
extraction; indirect BCOM index-type validation and its collateral approximation;
DBC fund expenses and Yahoo adjustments; and benchmark changes at both splices.
Open, High, Low and Volume remain blank throughout this synthetic growth series.
